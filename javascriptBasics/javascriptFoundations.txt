1. WHAT IS JAVASCRIPT? (CORE CHARACTERISTICS & HISTORY)
================================================================================

1. HISTORICAL CONTEXT:
   - Invented by Brendan Eich in May 1995 at Netscape Communications in just 10 days.
   - Original internal name: Mocha -> renamed to LiveScript -> renamed to JavaScript
     (a marketing move to capitalize on the popularity of Java at the time, though
     JavaScript and Java have fundamentally different architectures).
   - Standardized under Ecma International as ECMAScript (ECMA-262) in 1997.
   - Major milestone: ES6 (ECMAScript 2015), introducing let/const, arrow functions,
     classes, modules, promises, destructuring, and template literals.

2. FORMAL DEFINITION:
   JavaScript is a lightweight, cross-platform, single-threaded, dynamically typed,
   prototype-based, multi-paradigm, garbage-collected programming language with
   first-class functions and a non-blocking asynchronous event loop.

3. CORE CHARACTERISTICS EXPLAINED:

   a) Single-Threaded:
      - Has exactly ONE Call Stack.
      - Executes one instruction at a time sequentially.
      - Does not create native OS threads directly for JS code execution.

   b) Dynamically Typed:
      - Variable types are checked at runtime, not compile time.
      - Variables can change types during execution:
        let score = 99;         // Number
        score = "Ninety Nine";  // String (valid in JS)

   c) Multi-Paradigm:
      - Procedural (imperative functions and step-by-step logic)
      - Object-Oriented (prototype-based inheritance and class syntax)
      - Functional (first-class functions, higher-order functions: map, filter, reduce)

   d) First-Class Functions:
      - Functions are treated as first-class citizens (objects/values).
      - You can assign a function to a variable, pass it as an argument to another
        function, or return a function from another function.

   e) Automatic Garbage Collection:
      - Developers do not manually allocate or free memory (unlike malloc/free in C/C++).
      - The engine automatically tracks references and cleans up unreachable memory.

2. WHAT IS NODE.JS? (RUNTIME VS LANGUAGE, V8 + libuv ARCHITECTURE)
================================================================================

1. WHAT NODE.JS IS NOT:
   - Node.js is NOT a programming language.
   - Node.js is NOT a framework or a library.

2. WHAT NODE.JS ACTUALLY IS:
   Node.js is an open-source, cross-platform JavaScript Runtime Environment that
   allows developers to execute JavaScript code OUTSIDE of a web browser (on servers,
   terminals, and desktop operating systems).

   - Created by Ryan Dahl in 2009.
   - Dahl took Google Chrome's open-source V8 JavaScript engine, wrapped it with
     a high-performance C library called 'libuv', and exposed C++ bindings to
     operating system APIs (file system, network sockets, process control).

3. THE TWO PILLARS OF NODE.JS:

   +-----------------------------------------------------------------------+
   |                            NODE.JS RUNTIME                            |
   +-----------------------------------------------------------------------+
   |   1. V8 ENGINE (Google / C++)     |   2. libuv LIBRARY (C / Cross-OS) |
   |   - Parses JavaScript source code  |   - Event Loop implementation     |
   |   - Generates Bytecode (Ignition) |   - Asynchronous I/O polling      |
   |   - Compiles to Machine Code      |   - Internal Worker Thread Pool   |
   |   - Call Stack & Memory Heap      |   - Handles File System, DNS,     |
   |   - Garbage Collection            |     Network sockets, Child Proc   |
   +-----------------------------------+-----------------------------------+
   |             Node.js Native C++ Bindings & Core Standard Library       |
   |             (fs, path, http, crypto, os, events, stream, process)     |
   +-----------------------------------------------------------------------+

4. WHY NODE.JS REVOLUTIONIZED SOFTWARE:
   - Before Node.js (1995-2009): JavaScript could only run inside web browser sandboxes.
     Server-side code was written in PHP, Java, Python, Ruby, or C#.
   - After Node.js (2009-Present): A single developer can write JavaScript across the
     entire stack ("Full-Stack JavaScript"):
       Frontend: React, Vue, Svelte, Vanilla JS (in browser)
       Backend:  Express, NestJS, Fastify, Microservices (in Node.js)
       Tooling:  Vite, Webpack, Tailwind CLI, npm/pnpm, ESLint (all run on Node.js!)

4. HOW JAVASCRIPT EXECUTES CODE (THE V8 ENGINE PIPELINE)
================================================================================

When you execute:
$ node hello.js

The file contents are read from disk, and passed into Google's V8 engine.
Here is the exact lifecycle of how text becomes machine actions:

   [ Source Code (hello.js) ]
              |
              v
   [ 1. Stream & Scanner (Lexer) ] ---> Converts code string to TOKENS
              |
              v
   [ 2. Parser (Syntax Analysis) ] ---> Builds Abstract Syntax Tree (AST)
              |
              v
   [ 3. Ignition (Interpreter) ]   ---> Emits Register-based BYTECODE
              |
              +--------------------------+
              | (Executes Bytecode)      |
              v                          v
   [ 4. Feedback Vector ]         [ Call Stack Execution ]
              |
              | (Identifies "Hot" functions executed many times)
              v
   [ 5. TurboFan (JIT Compiler) ] ---> Generates OPTIMIZED MACHINE CODE
              |
              +<--- If types change dynamically? (Bailout / DEOPTIMIZE!)
              |
              v
   [ Direct Silicon Execution (x86_64 / ARM64 Assembly) ]


STEP-BY-STEP BREAKDOWN:

PHASE 1: STREAMING & ENCODING
- The file 'hello.js' is loaded from disk into memory as a byte stream (UTF-8 / UTF-16).
- V8 decodes the raw bytes into code points ready for lexical inspection.

PHASE 2: LEXICAL ANALYSIS (SCANNER / TOKENIZER)
- The Scanner reads the stream character-by-character and groups them into lexical TOKENS.
- Whitespace, newlines, and comments are stripped away.
- Each token is assigned a type (Keyword, Identifier, String, Punctuator, Number).

PHASE 3: PARSING (SYNTAX ANALYSIS & SCOPE RESOLUTION)
- The Parser takes the linear stream of tokens and converts it into a nested,
  hierarchical tree structure called the ABSTRACT SYNTAX TREE (AST).
- If there are syntax errors (e.g., missing parenthesis or unclosed quote),
  parsing stops immediately and throws a 'SyntaxError'.
- At this step, V8 also creates the Scope Tree (tracking variables, functions,
  and closures).

PHASE 4: BYTECODE GENERATION (THE IGNITION INTERPRETER)
- V8's interpreter, named IGNITION, traverses the AST and compiles it into
  clean, portable BYTECODE.
- What is Bytecode?
  - It is an intermediate, low-level instruction set (smaller than machine code,
    higher-level than raw assembly).
  - Bytecode allows JavaScript to start running almost instantaneously with very
    low memory overhead (crucial for mobile devices and fast page loads).

PHASE 5: EXECUTION & RUNTIME PROFILING (FEEDBACK VECTORS)
- Ignition begins executing the bytecode line-by-line inside the virtual machine.
- As it runs, Ignition tracks runtime behavior:
  - What types are being passed into functions?
  - Which functions are executed repeatedly ("Hot Code")?
- This metadata is stored in a "Feedback Vector".

PHASE 6: JIT COMPILATION & OPTIMIZATION (TURBOFAN)
- When a function becomes "hot" (e.g., called 10,000 times in a loop), V8 hands
  that function's bytecode AND its feedback vector to TURBOFAN (V8's optimizing JIT compiler).
- TurboFan makes speculative optimizations:
  - It assumes: "This function has received 2 integers every time; let's compile it
    directly into native machine code (CPU assembly) using fast CPU registers."
- The result is blazing fast raw binary execution directly on your CPU!

PHASE 7: DEOPTIMIZATION (DEOPT BAILOUT)
- JavaScript is dynamically typed. What if TurboFan assumed a function only takes
  numbers, but your code suddenly passes:
    add("hello", 42); // string instead of number!
- The speculative assumption is invalidated.
- TurboFan immediately discards the optimized machine code, triggers a "Bailout",
  and deoptimizes execution back to Ignition's safe bytecode interpreter.

5. AST DEEP DIVE: PARSING `console.log("Hello Chai!");`
================================================================================

Let us inspect the exact line of code in our 'hello.js' file:

   console.log("Hello Chai!");

1. TOKEN STREAM (Lexer Output):
   Token 1: Identifier  -> "console"
   Token 2: Punctuator  -> "."
   Token 3: Identifier  -> "log"
   Token 4: Punctuator  -> "("
   Token 5: String      -> "\"Hello Chai!\""
   Token 6: Punctuator  -> ")"
   Token 7: Punctuator  -> ";"

2. ABSTRACT SYNTAX TREE (AST Node Hierarchy):

   Program
     └── body: [1 item]
           └── ExpressionStatement
                 └── expression: CallExpression
                       ├── callee: MemberExpression
                       │     ├── object: Identifier (name: "console")
                       │     └── property: Identifier (name: "log")
                       └── arguments: [1 item]
                             └── Literal (value: "Hello Chai!", raw: "\"Hello Chai!\"")

3. WHY AST MATTERS:
   - Tooling like Babel, TypeScript, ESLint, Prettier, and SWC all work by
     parsing your code into an AST, transforming nodes in the tree, and emitting
     the result back out as JavaScript!

6. MEMORY HEAP, CALL STACK & EXECUTION CONTEXT
================================================================================

1. MEMORY HEAP:
   - An unstructured memory region used for dynamic memory allocation.
   - Objects, arrays, functions, and complex data structures are stored here.
   - Monitored and cleaned by V8's Garbage Collector (Orinoco).

2. CALL STACK (EXECUTION STACK):
   - A Last-In, First-Out (LIFO) data structure that keeps track of the currently
     executing function calls.
   - When a function is called, an Execution Context is pushed to the top of the stack.
   - When the function returns, its Execution Context is popped off the stack.
   - If too many nested functions call each other without returning, you get:
     "Maximum call stack size exceeded" (Stack Overflow).

3. EXECUTION CONTEXT (THE INNER WORKINGS):
   Every time JavaScript code runs, it runs inside an Execution Context.
   There are 2 main types:
   - Global Execution Context (GEC): Created once when the script starts.
   - Function Execution Context (FEC): Created whenever a function is invoked.

   EVERY EXECUTION CONTEXT HAS TWO PHASES:

   PHASE A: CREATION PHASE (MEMORY ALLOCATION / HOISTING)
   - The engine scans code for declarations BEFORE executing a single line.
   - Creates the Global Object (`window` in browser, `global` in Node.js).
   - Sets up the `this` binding.
   - Allocates memory for variables and functions:
     * `var` variables are allocated and assigned `undefined`.
     * `let` and `const` variables are allocated in the Temporal Dead Zone (TDZ)
       (uninitialized; accessing them before definition throws ReferenceError).
     * `function` declarations are placed into memory with their entire definition!

   PHASE B: EXECUTION PHASE (CODE EXECUTION)
   - The engine executes the code line-by-line from top to bottom.
   - Variables are assigned their actual values.
   - Functions are invoked, creating new child Function Execution Contexts.

7. CONCURRENCY & THE EVENT LOOP (libuv & ASYNC JS)
================================================================================

Because JavaScript is single-threaded, how does Node.js handle thousands of
concurrent network requests, file reading, and timers without freezing?

Answer: THE EVENT LOOP (powered by libuv in Node.js).

+--------------------------------------------------------------------------+
|                               EVENT LOOP                                 |
+--------------------------------------------------------------------------+
|                                                                          |
|   1. CALL STACK (V8 Engine)                                              |
|      - Executes synchronous code line-by-line.                           |
|      - When an async function (e.g. fs.readFile, setTimeout) is called,  |
|        it is handed off to libuv / Node APIs and popped off the stack!   |
|                                                                          |
|   2. NODE.JS WORKER THREAD POOL (libuv)                                  |
|      - Handles heavy blocking tasks in background C/C++ threads:         |
|        * File System I/O (fs)                                            |
|        * DNS lookups                                                     |
|        * Cryptography (crypto.pbkdf2)                                    |
|        * Zlib compression                                                |
|                                                                          |
|   3. MICROTASK QUEUE (HIGHEST PRIORITY)                                  |
|      - process.nextTick() callbacks                                      |
|      - Resolved Promise callbacks (.then, .catch, .finally)              |
|      - queueMicrotask()                                                  |
|      * Emptied COMPLETELY after every synchronous stack operation!       |
|                                                                          |
|   4. MACROTASK / CALLBACK QUEUE                                          |
|      - Timers (setTimeout, setInterval)                                  |
|      - I/O events (network packets, file read complete)                  |
|      - setImmediate() callbacks                                          |
|      - Close events (socket.on('close'))                                 |
|                                                                          |
|   5. THE EVENT LOOP MONITOR                                              |
|      - Constantly checks: "Is the Call Stack empty?"                     |
|      - When the Call Stack is empty, it moves pending callbacks from     |
|        the queues onto the Call Stack for execution.                     |
+--------------------------------------------------------------------------+

9. PART 1: PRINTING METHODS IN JS (printing.js)
================================================================================

In Node.js, there are several distinct ways to output text and data to the console:

1. console.log(...data):
   - The standard utility for standard output.
   - Automatically appends a newline character (\n) at the end of each call.
   - Example:
     console.log("Hello");
     console.log("World");
     // Output:
     // Hello
     // World

2. process.stdout.write(string):
   - Lower-level stream output provided directly by Node.js.
   - Does NOT append an automatic newline!
   - Can print subsequent outputs consecutively on the exact same terminal line.
   - Requires a string (does not auto-serialize objects like console.log).
   - Example (from part1/printing.js):
     process.stdout.write("Chai");
     process.stdout.write("Chai");
     // Output: ChaiChai (on the same line!)

3. console.table(tabularData):
   - Formats arrays and objects into a clean, readable ASCII table with index/key columns.
   - Example (from part1/printing.js):
     console.table({ city: "Varanasi" });
     // Output:
     // ┌─────────┬────────────┐
     // │ (index) │   Values   │
     // ├─────────┼────────────┤
     // │  city   │ 'Varanasi' │
     // └─────────┴────────────┘

10. PART 1: DATA TYPES & THE VAR VS LET VS CONST DEEP DIVE (datatype.js)
================================================================================

JavaScript data types fall into two foundational categories:

CATEGORY 1: PRIMITIVE DATA TYPES (Call by Value)
- Stored directly in Stack memory.
- When copied, a new copy of the actual value is created.
- 7 Built-in Primitives:
  1. String   : "chaicode.com", 'hello', `tea`
  2. Number   : 102, 3.14, -42 (IEEE 754 64-bit float; max safe int: 2^53 - 1)
  3. BigInt   : 9007199254740991n (for values exceeding 2^53 - 1)
  4. Boolean  : true or false
  5. undefined: A variable declared but not yet assigned a value
  6. null     : Standalone primitive representing the deliberate absence of value
  7. Symbol   : Symbol("id") creates a guaranteed unique, immutable identifier

* NOTE ON typeof null:
  console.log(typeof null); // "object"
  This is a famous historical bug in JavaScript dating back to 1995. In the original
  JS implementation, values were represented with type tags. The tag '000' represented
  an object, and null was represented as a NULL pointer (0x00), resulting in typeof
  returning "object". It cannot be fixed today without breaking millions of websites.

CATEGORY 2: NON-PRIMITIVE / REFERENCE TYPES (Call by Reference)
- Stored in the Memory Heap.
- Variables store only a memory reference (pointer) to the heap location.
- Includes:
  1. Arrays   : let teaTypes = ["lemon tea", "orange tea", "oolong tea"];
  2. Objects  : let user = { firstname: "Ali", lastname: "Sayeed" };
  3. Functions: function brewTea() { ... }


--------------------------------------------------------------------------------
THE DEFINITIVE COMPARISON: var vs let vs const
--------------------------------------------------------------------------------

Feature          | var (Legacy - ES5)       | let (Modern - ES6)       | const (Modern - ES6)
-----------------+--------------------------+--------------------------+--------------------------
Scope            | FUNCTION-SCOPED          | BLOCK-SCOPED { }         | BLOCK-SCOPED { }
Re-assignment    | Allowed anytime          | Allowed anytime          | FORBIDDEN (TypeError)
Re-declaration   | Allowed (causes bugs!)   | FORBIDDEN (SyntaxError)  | FORBIDDEN (SyntaxError)
Initialization   | Optional (default undef) | Optional (default undef) | MANDATORY at declaration
Hoisting         | Hoisted to undefined     | Hoisted into TDZ         | Hoisted into TDZ
Temporal Dead Zon| No TDZ (returns undef)   | Yes (ReferenceError)     | Yes (ReferenceError)
Global Property  | Attaches to window/global| Does NOT attach to global| Does NOT attach to global

1. SCOPE DIFFERENCE (The Block Leak Problem):
   {
       var a = 10;
       let b = 20;
       const c = 30;
   }
   console.log(a); // 10  (var ignores the block! Leaks outside!)
   console.log(b); // ReferenceError: b is not defined (Properly contained!)
   console.log(c); // ReferenceError: c is not defined (Properly contained!)

2. RE-DECLARATION (The Silent Bug):
   var score = 100;
   var score = 200; // Silently overwrites score! High risk of collisions.

   let points = 100;
   // let points = 200; // SyntaxError: Identifier 'points' has already been declared.

3. CONST WITH OBJECTS & ARRAYS (Mutation vs Reassignment):
   const chaiOrder = { type: "Masala Chai", sugar: true };
   
   // A. Mutating a property is ALLOWED:
   chaiOrder.sugar = false; // Valid! The internal object data mutated.
   
   // B. Reassigning the identifier is FORBIDDEN:
   // chaiOrder = {}; // TypeError: Assignment to constant variable.

MODERN BEST PRACTICE GUIDELINES:
1. Always use 'const' by default for all variables, objects, arrays, and functions.
2. Use 'let' only when you specifically need the variable value to change (e.g., loop counters, accumulators).
3. NEVER use 'var' in modern JavaScript to eliminate scope leaks and unpredictable hoisting behavior.

11. PART 1: OPERATIONS, EXPRESSIONS & COMPARISONS (operations.js)
================================================================================

JavaScript provides a complete set of operators to manipulate numbers, strings,
and evaluate boolean logic:

1. ARITHMETIC OPERATORS:
   Operator | Name           | Example     | Result
   ---------+----------------+-------------+--------
   +        | Addition       | 4 + 5       | 9
   -        | Subtraction    | 9 - 3       | 6
   *        | Multiplication | 3 * 5       | 15
   /        | Division       | 8 / 2       | 4
   %        | Modulo/Remainder| 9 % 2      | 1  (9 divided by 2 gives remainder 1)
   **       | Exponentiation | 2 ** 3      | 8  (2 to the power of 3: 2 * 2 * 2)

2. INCREMENT (++) & DECREMENT (--) OPERATORS:
   - Modifies the variable directly by adding or subtracting 1.
   
   A. Postfix (x++ / x--):
      - Evaluates the CURRENT value first, then increments/decrements.
      let a = 5;
      let b = a++; // b = 5, then a becomes 6!

   B. Prefix (++x / --x):
      - Increments/decrements FIRST, then evaluates the updated value.
      let x = 5;
      let y = ++x; // x becomes 6, then y = 6!

   In operations.js:
   let myscore = 110;
   myscore++; // myscore is now 111
   let credits = 56;
   credits--; // credits is now 55

3. COMPARISON OPERATORS:
   Used in decision-making and conditionals. Always returns a Boolean (true or false).

   Operator | Meaning                  | Example (num1=3, num2=3, num3=6) | Result
   ---------+--------------------------+-----------------------------------+--------
   ==       | Loose Equality (coercion)| num1 == num2  (3 == 3)            | true
   !=       | Loose Inequality         | num1 != num3  (3 != 6)            | true
   >        | Greater Than             | num1 > num3   (3 > 6)             | false
   <        | Less Than                | num1 < num3   (3 < 6)             | true
   >=       | Greater Than or Equal To | num1 >= num2  (3 >= 3)            | true
   <=       | Less Than or Equal To    | num1 <= num3  (3 <= 6)            | true

   CRITICAL INTERVIEW CONCEPT: == (Loose) vs === (Strict)
   - '==' (Loose Equality): Compares values ONLY after performing implicit type coercion.
     console.log("3" == 3);      // true! (String "3" is converted to Number 3)
     console.log(null == undefined); // true!
     console.log(false == 0);    // true!

   - '===' (Strict Equality): Compares BOTH value AND data type without coercion.
     console.log("3" === 3);     // false! (String !== Number)
     console.log(null === undefined); // false!
     console.log(false === 0);   // false!

   * GOLDEN RULE: Always prefer '===' and '!==' to avoid subtle type coercion bugs!

4. TYPE COERCION & OPERATOR PRECEDENCE GOTCHAS:
   In JavaScript, the '+' operator serves double duty for both numeric addition
   AND string concatenation. When strings and numbers are mixed:
   
   console.log("1" + 2);       // "12"   (number 2 coerced to string)
   console.log(1 + "2");       // "12"   (number 1 coerced to string)
   console.log(1 + 2 + "3");   // "33"   (1 + 2 executes first -> 3 + "3" -> "33")
   console.log("1" + 2 + 3);   // "123"  ("1" + 2 -> "12" + 3 -> "123")
   
   Rule of Thumb: Write explicit conversion methods (e.g. Number(str) or String(num))
   or use parentheses ( ) to make calculation intent completely unambiguous.

12. PART 1: ASSIGNMENT, LOGICAL OPERATORS & PRECEDENCE
================================================================================

This module covers the core building blocks from:
- assignment.js
- logical.js
- operatorprecedence.js


1. ASSIGNMENT OPERATORS (assignment.js):
   Assignment operators store and update values in memory variables.

   Operator | Name                  | Equivalent Expansion   | Example
   ---------+-----------------------+------------------------+--------------------
   =        | Simple Assignment     | x = y                  | let num1 = 10;
   +=       | Addition Assignment   | x = x + y              | num1 += 5; (15)
   -=       | Subtraction Assign    | x = x - y              | num1 -= 2; (13)
   *=       | Multiplication Assign | x = x * y              | num1 *= 2; (26)
   /=       | Division Assignment   | x = x / y              | num1 /= 5; (3)
   %=       | Modulo Assignment     | x = x % y              | num1 %= 2; (1)
   **=      | Exponentiation Assign | x = x ** y             | num1 **= 3; (8)

   Walkthrough of 'assignment.js':
   let score = 10 + 11; // score = 21
   let num1 = 10;
   num1 = num1 + 5;     // num1 becomes 15
   num1 /= 5;           // Equivalent to: num1 = num1 / 5 (15 / 5 = 3)
   console.log(num1);   // Outputs: 3


2. LOGICAL OPERATORS (logical.js):
   Used to combine or invert boolean evaluations in control flow and decision gates:

   Operator | Name        | Behavior
   ---------+-------------+-------------------------------------------------------------
   &&       | Logical AND | Returns true ONLY if BOTH left and right operands are true.
   ||       | Logical OR  | Returns true if AT LEAST ONE operand is true.
   !        | Logical NOT | Inverts truthiness: !true -> false, !false -> true.

   A. Logical AND (&&) - Authentication & Permission Gate:
      let isLoggedin = true;
      let ispaid = true;
      console.log(isLoggedin && ispaid); // true
      // If either is false, access is denied (evaluates to false).

   B. Logical OR (||) - Multi-Provider Sign-In Gate:
      let isEmailuser = true;
      let isGoogleuser = false;
      console.log(isEmailuser || isGoogleuser); // true
      // As long as the user logs in via at least ONE provider, entry is allowed.

   C. Short-Circuit Evaluation:
      In JavaScript, logical operators stop evaluating as soon as the result is determined:
      - '&&' short-circuits on the FIRST falsy value (stops immediately).
      - '||' short-circuits on the FIRST truthy value (stops immediately).

   D. The 8 Falsy Values in JavaScript:
      Every value in JS is "truthy" EXCEPT these 8 falsy values:
      1. false
      2. 0
      3. -0
      4. 0n (BigInt zero)
      5. "" (empty string)
      6. null
      7. undefined
      8. NaN (Not a Number)


3. OPERATOR PRECEDENCE & GROUPING (operatorprecedence.js):
   Operator precedence determines the order in which operators are parsed and evaluated.

   Common Precedence Order (Higher runs first):
   Precedence | Operator Category | Operators
   -----------+-------------------+----------------------------
   18 (Highest| Grouping          | ( ... )
   13         | Multiplication/Div| * , / , %
   12         | Addition/Subtract | + , -
   9          | Relational        | < , <= , > , >=
   8          | Equality          | == , != , === , !==
   4          | Logical AND       | &&
   3          | Logical OR        | ||
   2 (Lowest) | Assignment        | = , += , -= , /= , *=

   Walkthrough of 'operatorprecedence.js':
   let score = ((2 * (3 + 2)) - 1);
   Step 1: Inner parentheses evaluated first: (3 + 2) -> 5
   Step 2: Multiplication inside next parentheses: (2 * 5) -> 10
   Step 3: Subtraction evaluated: (10 - 1) -> 9
   console.log(score); // Outputs: 9

   PROFESSIONAL CLEAN CODE RULE:
   Do NOT rely on teammates memorizing the 18 levels of operator precedence.
   Always use explicit parentheses '( )' to make calculation intent completely clear.

13. PART 2: PRIMITIVES VS OBJECT WRAPPERS & AUTOBOXING (primitives.js)
================================================================================

In JavaScript, there is a fundamental distinction between raw primitive values
and their object wrapper counterparts:

1. PRIMITIVE LITERALS VS OBJECT WRAPPERS:
   - Literal declaration (Standard & Recommended):
     let balance = 120;
     console.log(typeof balance); // "number"

   - Object Wrapper constructor (NOT recommended):
     let anotherBalance = new Number(120);
     console.log(typeof anotherBalance); // "object"!

   A. Why 'balance === anotherBalance' is FALSE:
      - 'balance' is a raw primitive number stored in stack memory.
      - 'anotherBalance' is an instance of the Number object stored in the heap.
      - Because strict equality (===) compares both type and memory identity,
        a primitive number will never equal an object wrapper!

   B. The '.valueOf()' Method:
      - Extracts the raw primitive value from an object wrapper:
      anotherBalance.valueOf(); // 120 (returns raw primitive number)

   C. The 'new Boolean()' Trap:
      let isActive = true;
      let isReallyActive = new Boolean(false); // Dangerous!
      // In JavaScript, ANY object (even an empty object or new Boolean(false))
      // is TRUTHY when evaluated in an if-statement!
      if (isReallyActive) {
          // This code RUNS even though it wrapped 'false'!
      }

2. AUTOBOXING (HOW PRIMITIVES CALL METHODS):
   - If primitives are not objects, why can we write:
     "hello".toUpperCase();
     (120.456).toFixed(2);
   - Behind the scenes, the V8 engine performs AUTOBOXING:
     1. It temporarily wraps the primitive in a transient Object wrapper (new String / new Number).
     2. It executes the prototype method.
     3. It immediately discards and garbage-collects the temporary wrapper object.
   - Result: You get the performance and memory efficiency of raw primitives with
     the convenience of object methods!

3. TEMPLATE LITERALS VS STRING CONCATENATION:
   - Old style (plus operator):
     let oldGreet = myString + " " + myName; // Error-prone, noisy with spaces

   - Modern ES6 Template Literals (Backticks `...`):
     let newGreet = `${myString} ${myName}`;
     * Supports embedded expressions: `${2 + 2}` -> `4`
     * Supports multiline strings without `\n` escape sequences.

4. SYMBOLS (UNIQUE IDENTIFIERS):
   - let sm1 = Symbol("Ali");
   - let sm2 = Symbol("Ali");
   - console.log(sm1 === sm2); // false!
   - Every Symbol is guaranteed to be globally unique and immutable, commonly used
     as non-colliding object keys or library metadata.

14. PART 2: NON-PRIMITIVES, OBJECT ACCESS & TYPE COERCION (nonPrimitives.js)
================================================================================

1. OBJECTS & PROPERTY ACCESS:
   const username = {
       "first name": "Hitesh",
       isLoggedin: true
   };

   A. Dot Notation:
      - username.isLoggedin (Standard, clean access)
      - CANNOT be used when the key contains spaces, dashes, starts with numbers,
        or is stored in a dynamic variable:
        // username.first name -> SyntaxError!

   B. Bracket Notation:
      - username["first name"] (Mandatory for keys with spaces/special characters)
      - Also required when the key name is evaluated dynamically from a variable:
        let key = "first name";
        console.log(username[key]); // "Hitesh"

   C. Adding / Modifying Properties on 'const' Objects:
      username.lastname = "Choudhary";
      // Works perfectly! 'const' prevents reassignment of the variable reference,
      // but does NOT freeze internal object property mutations.

2. BUILT-IN REFERENCE OBJECTS:
   - Date Object:
     let today = new Date();
     console.log(today.getDate()); // Returns current calendar day of month (1-31)
   
   - Arrays:
     let anotherUser = ["Ali", true];
     console.log(anotherUser[0]); // "Ali" (0-indexed heterogeneous collection)

3. EXPLICIT TYPE CONVERSION & COERCION TRAPS:
   JavaScript provides constructor functions (without 'new') for explicit type casting:

   A. Number("2abc") -> NaN:
      let isValue = "2abc";
      let converted = Number(isValue); // NaN (Not a Number)
      console.log(typeof converted);   // "number"
      * FAMOUS INTERVIEW QUESTION: What is typeof NaN?
        Answer: "number"! In JavaScript, NaN is a numeric value representing an
        unrepresentable or failed mathematical operation.

   B. Conversion Matrix for Number():
      Input Value          | Number(Input) Result
      ---------------------+---------------------
      "123"                | 123
      "2abc"               | NaN
      null                 | 0
      undefined            | NaN
      true                 | 1
      false                | 0
      "" (empty string)    | 0

-----------------+------------------------------------------------------------------
JavaScript       | High-level, single-threaded, dynamically typed scripting language

Memory Heap      | Unstructured memory region storing objects, arrays, and closures
Hoisting         | Moving variable/function declarations to memory in creation phase
Temporal Dead Zon| Zone between block start and 'let/const' declaration (TDZ)
Primitive Types  | 7 basic types (string, number, bigint, boolean, undefined, null, symbol)
Reference Types  | Objects, arrays, functions stored in heap memory (call by reference)

Symbol           | Guaranteed unique and immutable primitive used for safe object keys
NaN              | Not-a-Number: Special numeric value representing a failed calculation

Loose Equality   | '==' operator checking values with implicit type coercion
Compound Assign  | Shorthand updating and assigning a variable in one step (+=, /=)

Precedence       | Order in which operators are evaluated (parentheses have highest precedence)
Event Loop       | Coordinator shifting callbacks from queues onto the Call Stack
