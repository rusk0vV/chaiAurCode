Project 01: Dark-Mode To-Do List Architecture (01_todo-localstorage)

Structural Markup & Dark-Theme Flexbox Layout (index.html & styles.css) UI & Layout Layer

The Dark Mode To-Do List project (01_todo-localstorage) is a foundational CRUD (Create, Read, Update, Delete) web application built with vanilla HTML5, CSS3, and JavaScript. It pairs a centered Flexbox card layout (#1e1e1e card over a #121212 dark canvas) with an interactive input bar (#todo-input and #add-task-btn) and a dynamically populated unordered list container (#todo-list).

PHASE 01 • HYDRATE
Boot & Parse Storage

On DOMContentLoaded, read serialized JSON tasks from localStorage and render existing items into #todo-list.

PHASE 02 • CREATE
Capture & Append Task

Trim input string, build a task object with id: Date.now(), push to tasks array, persist, and append <li>.

PHASE 03 • MUTATE
Toggle or Delete

Click <li> to toggle completion state (.completed CSS class) or click <button> to remove the item and sync storage.

UI & Styling Highlights (index.html & styles.css)
Viewport Centering: The body uses display: flex; justify-content: center; align-items: center; height: 100vh; to keep the 300px application card centered across screen sizes.
Visual State Feedback (li.completed): Completed tasks receive the .completed class, applying text-decoration: line-through; and opacity: 0.7; to visually distinguish finished items.
Semantic Action Colors: Primary task creation uses deep violet (#6200ea → #3700b3 on hover), while destructive delete actions use crimson red (#d32f2f → #b71c1c on hover).

State Management & Browser LocalStorage Persistence (script.js)

JSON Serialization, Hydration & Task Object Schema Web Storage API

Browser variables stored in RAM are wiped whenever a user refreshes or closes the tab. To achieve persistence without a backend database, script.js uses the browser's window.localStorage API. Because localStorage can only store key-value pairs as strings, JavaScript arrays and objects must be serialized using JSON.stringify() before saving and deserialized with JSON.parse() when loading.

State & Storage Mechanics in script.js
Safe Fallback Initialization: let tasks = JSON.parse(localStorage.getItem("tasks")) || []; ensures that on the very first visit—when localStorage.getItem("tasks") returns null—the short-circuit OR operator (||) initializes an empty array instead of throwing a TypeError on tasks.forEach().
Task Data Model: Every task is stored as a structured object: { id: Date.now(), text: taskText, completed: false }. Using Date.now() provides a millisecond-precision timestamp as a unique identifier.
Input Sanitization: todoInput.value.trim() strips leading and trailing whitespace, and if (taskText === "") return; guards against adding blank tasks.
// script.js — Lifecycle Boot, State Hydration & Task Creation
document.addEventListener("DOMContentLoaded", () => {
  const todoInput = document.getElementById("todo-input");
  const addTaskButton = document.getElementById("add-task-btn");
  const todoList = document.getElementById("todo-list");

  // Hydrate persisted tasks from localStorage or fall back to empty array
  let tasks = JSON.parse(localStorage.getItem("tasks")) || [];
  tasks.forEach((task) => renderTask(task));

  addTaskButton.addEventListener("click", () => {
    const taskText = todoInput.value.trim();
    if (taskText === "") return;

    const newTask = { id: Date.now(), text: taskText, completed: false };
    tasks.push(newTask);
    saveTasks();
    renderTask(newTask);
    todoInput.value = ""; // clear input
  });

  function saveTasks() {
    localStorage.setItem("tasks", JSON.stringify(tasks));
  }
});

Dynamic DOM Rendering & Event Propagation Control

renderTask(), e.stopPropagation() & Array Filtering Nuance DOM & Event Architecture

The renderTask(task) function constructs an <li> element in memory, attaches custom metadata via li.setAttribute("data-id", task.id), and wires up two distinct click listeners: one on the <li> container for toggling task completion, and one on the child <button> for deleting the task. Managing how clicks travel between the child button and parent list item is a classic demonstration of DOM Event Bubbling.

Event Propagation & State Filtering Details
Preventing Event Bubbling (e.stopPropagation): Because the <button> sits inside the <li>, clicking "delete" would normally bubble up and trigger the <li> click listener as well. Calling e.stopPropagation() inside the button handler halts upward propagation immediately.
Target Tag Guard: As a secondary defense, the <li> listener checks if (e.target.tagName === "BUTTON") return; so clicks originating on the button never toggle completion.
Filter Predicate Watchout (=== vs !==): In script.js line 43, tasks = tasks.filter((t) => t.id === task.id) keeps the clicked task in the array; to exclude the deleted task from localStorage, the predicate should use strict inequality: t.id !== task.id.
// script.js — Dynamic Element Construction & Bubbling Control
function renderTask(task) {
  const li = document.createElement("li");
  li.setAttribute("data-id", task.id);
  if (task.completed) li.classList.add("completed");
  li.innerHTML = `
    <span>${task.text}</span>
    <button>delete</button>
  `;

  // Toggle completion status when clicking the list item
  li.addEventListener("click", (e) => {
    if (e.target.tagName === "BUTTON") return;
    task.completed = !task.completed;
    li.classList.toggle("completed");
    saveTasks();
  });

  // Delete task and stop click event from bubbling up to parent <li>
  li.querySelector("button").addEventListener("click", (e) => {
    e.stopPropagation(); // prevent toggle from firing
    tasks = tasks.filter((t) => t.id !== task.id);
    li.remove();
    saveTasks();
  });

  todoList.appendChild(li);
}
