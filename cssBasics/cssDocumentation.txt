================================================================================
                           CSS BASICS - COMPREHENSIVE STUDY NOTES
================================================================================

1. WHAT IS CSS?
--------------------------------------------------------------------------------
CSS stands for Cascading Style Sheets. It controls the visual presentation, styling,
colors, typography, spacing, dimensions, and layout of HTML elements. While HTML
provides the skeleton/structure, CSS provides the skin/design.


================================================================================
2. THE 3 WAYS TO APPLY CSS & SPECIFICITY
================================================================================

1. INLINE CSS:
   - Written directly within the HTML element's "style" attribute.
   - Example: <h1 style="color: orangered;">Title</h1>
   - Highest specificity priority (overrides internal and external stylesheets).
   - Best for quick testing; avoid in large projects due to poor maintainability.

2. INTERNAL CSS (EMBEDDED):
   - Written inside a <style> ... </style> block inside the HTML document's <head>.
   - Example:
     <head>
         <style>
             .browntext { color: brown; }
         </style>
     </head>
   - Scoped strictly to that single HTML file.

3. EXTERNAL CSS (INDUSTRY STANDARD):
   - Written in a dedicated .css file (e.g. style.css) and linked in <head> via:
     <link rel="stylesheet" href="style.css" />
   - Cleanest separation of concerns, reusable across many pages, and cached by
     browsers for superior loading speed.

SPECIFICITY CASCADE ORDER:
Inline Style > Internal/External Stylesheet > Browser Default Styles


================================================================================
3. CSS SELECTORS & COMBINATORS
================================================================================

A selector determines which HTML element(s) to target and apply styles to.
CSS provides simple selectors, combinators, attribute selectors, pseudo-classes,
and pseudo-elements:

1. UNIVERSAL SELECTOR (*):
   - Targets every single element on the HTML page.
   - Most commonly used for global resets and enforcing consistent box-sizing.
   - Syntax:
     * {
         margin: 0;
         padding: 0;
         box-sizing: border-box;
     }

2. ELEMENT (TYPE) SELECTOR:
   - Targets all elements matching the given HTML tag name.
   - Syntax:
     p {
         font-size: 16px;
         margin-bottom: 10px;
     }

3. CLASS SELECTOR (.):
   - Targets any element with a matching class="name" attribute.
   - Prefixed with a period (.). Reusable across multiple elements on the same page.
   - Syntax:
     .highlight {
         background-color: #21a2c9;
     }

4. ID SELECTOR (#):
   - Targets a unique element having a specific id="name" attribute.
   - Prefixed with a hash (#). An ID must be unique per HTML page.
   - Carries higher specificity than classes or element selectors.
   - Syntax:
     #header {
         background-color: #860303;
     }

5. ATTRIBUTE SELECTOR ([attribute="value"]):
   - Targets elements based on the presence or exact value of an HTML attribute.
   - Extremely useful for form inputs and custom data attributes.
   - Syntax:
     input[type="text"] {
         border: 2px solid #21a2c9;
     }

6. DESCENDANT COMBINATOR (space):
   - Targets all specified elements nested inside an ancestor, regardless of depth
     (children, grandchildren, great-grandchildren, etc.).
   - Syntax:
     article p {
         font-style: italic;
         background-color: #1a1a1a;
         color: #fff;
         padding: 10px;
     }

7. CHILD COMBINATOR (>):
   - Targets ONLY direct (immediate) children of a parent element.
   - Ignores nested grandchildren or deeper descendants.
   - Syntax:
     div > p {
         background-color: #880404;
     }

8. ADJACENT SIBLING COMBINATOR (+):
   - Targets the immediate next sibling element that directly follows another element
     at the same nesting level.
   - Syntax:
     h1 + p {
         font-weight: bold;
     }

9. GENERAL SIBLING COMBINATOR (~):
   - Targets all sibling elements following a specified element under the same parent,
     even if they are separated by other elements.
   - Syntax:
     h2 ~ p {
         color: #860303;
     }

10. PSEUDO-CLASS SELECTOR (:):
    - Targets an element based on its dynamic interaction state or position.
    - Examples: :hover, :focus, :active, :visited, :first-child.
    - Syntax:
      a:hover {
          background-color: #14a50e;
          text-decoration: none;
          color: #1a1a1a;
          padding: 5px;
          margin: 4px;
      }

11. PSEUDO-ELEMENT SELECTOR (::):
    - Targets and styles a specific piece or sub-part of an element's content.
    - Examples: ::first-letter, ::first-line, ::before, ::after, ::selection.
    - Syntax:
      p::first-letter {
          font-weight: bold;
          font-size: 30px;
      }

12. GROUPING SELECTOR (,):
    - Combines multiple different selectors so they share the exact same style declarations.
    - Reduces repetitive CSS code (DRY - Don't Repeat Yourself).
    - Syntax:
      h1, h2, h3 {
          color: orange;
      }

SELECTOR SPECIFICITY HIERARCHY:
!important > Inline styles > IDs (#) > Classes (.), Attributes ([ ]), Pseudo-classes (:) > Elements (tag), Pseudo-elements (::) > Universal (*)

4. THE CSS BOX MODEL & DISPLAY TYPES
================================================================================

Every HTML element is treated by the browser as a rectangular box composed of 4
concentric layers:

 [----------------------- MARGIN -----------------------]
 |   [------------------ BORDER -------------------]    |
 |   |   [------------- PADDING --------------]    |    |
 |   |   |                                    |    |    |
 |   |   |             CONTENT                |    |    |
 |   |   |         (Text, Images)             |    |    |
 |   |   |                                    |    |    |
 |   |   [------------------------------------]    |    |
 |   [---------------------------------------------]    |
 [------------------------------------------------------]

1. THE 4 CONCENTRIC LAYERS:
   - CONTENT: The actual content of the box where text, media, and images appear.
   - PADDING: The transparent spacing *inside* the border, around the content.
     * padding: 20px; (gives breathing room between border and content)
   - BORDER: The edge/boundary line enclosing padding and content.
     * border: 5px solid #333; (width, line-style, color)
     * border-radius: 8px; (rounds corners)
   - MARGIN: The transparent spacing *outside* the border, pushing adjacent elements away.
     * margin: 30px; (pushes surrounding elements away)
     * margin: 0; (resets default browser margin)

2. BOX SIZING (content-box VS border-box):
   The box-sizing property determines how total rendered width and height are calculated.

   A. CONTENT-BOX (BROWSER DEFAULT):
      - width and height apply ONLY to the inner content area.
      - Any padding and border are ADDED on top of width/height!
      - Formula:
        Total Rendered Width = width + padding-left + padding-right + border-left + border-right
        Total Rendered Height = height + padding-top + padding-bottom + border-top + border-bottom
      - Example (from boxmodel.html):
        width: 300px; height: 200px; padding: 20px; border: 5px solid #333;
        -> Total Width = 300px + 40px (padding) + 10px (border) = 350px!
        -> Total Height = 200px + 40px (padding) + 10px (border) = 250px!
      - Drawback: Adding padding causes boxes to grow larger and break layouts/grids.

   B. BORDER-BOX (INDUSTRY BEST PRACTICE):
      - width and height represent the ENTIRE rendered box, INCLUDING padding and border!
      - Formula:
        Total Rendered Width = declared width (e.g., exactly 300px)
        Total Rendered Height = declared height (e.g., exactly 200px)
        Inner Content Width = width - (padding + border)
      - Example (from boxmodel.html):
        width: 300px; height: 200px; padding: 20px; border: 5px solid #333;
        -> Total Width remains strictly 300px! (Content area shrinks to 250px)
        -> Total Height remains strictly 200px! (Content area shrinks to 150px)
      - Why it's used in global reset:
        * {
            box-sizing: border-box;
        }
        Makes UI predictable and prevents unexpected sizing overflow.

3. ELEMENT DISPLAY BEHAVIORS (INLINE vs BLOCK vs INLINE-BLOCK):
   The display property defines how elements lay out in relation to surrounding content.

   A. INLINE ELEMENTS (display: inline; e.g. <span>, <a>, <strong>):
      - Do NOT start on a new line; flow along with text on the same line.
      - Take up only as much width as necessary (shrink to fit content).
      - CRITICAL: IGNORE declared width and height properties!
        (e.g., width: 200px; height: 100px; have NO effect on an inline <span>).
      - Vertical margins (top/bottom) do not push away surrounding lines of text.

   B. BLOCK-LEVEL ELEMENTS (display: block; e.g. <div>, <p>, <h1>-<h6>, <section>):
      - Always start on a new line (line break before and after).
      - Expand to fill the full 100% available width of their parent container.
      - Fully RESPECT width, height, padding, and margin in all four directions.

   C. INLINE-BLOCK ELEMENTS (display: inline-block; e.g. .highlight):
      - The perfect hybrid:
        1. Flows inline alongside other elements on the same line (like inline).
        2. Fully respects width, height, padding, and margin (like block)!
      - Example:
        .highlight {
            background-color: yellow;
            display: inline-block;
        }

5. MODERN FLEXBOX LAYOUT (FLEXBOX MASTERCLASS)
================================================================================

Flexbox (Flexible Box Layout) is a 1-dimensional CSS layout model designed to
distribute space and align items along horizontal and vertical axes effortlessly.

CRITICAL MENTAL MODEL: MAIN AXIS vs CROSS AXIS
--------------------------------------------------------------------------------
Flexbox works along two perpendicular axes:
- MAIN AXIS:  The primary axis along which flex items flow.
              Default is HORIZONTAL (left-to-right) when flex-direction: row.
              Controlled by: justify-content.
- CROSS AXIS: The perpendicular axis to the main axis.
              Default is VERTICAL (top-to-bottom) when flex-direction: row.
              Controlled by: align-items (single row) and align-content (multi-row).
* When flex-direction: column is used, the axes SWAP:
  Main axis becomes VERTICAL; Cross axis becomes HORIZONTAL!

--------------------------------------------------------------------------------
5.1. FLEX CONTAINER PROPERTIES (APPLIED TO PARENT)
--------------------------------------------------------------------------------

1. display: flex; (or display: inline-flex;)
   - Transforms the parent element into a Flex Container.
   - All immediate child elements automatically become Flex Items.
   - Default behavior: Items line up side-by-side in a horizontal row without line breaks.

2. flex-direction: row | column | row-reverse | column-reverse;
   - Sets the direction of the Main Axis:
     * row (default): Items flow left to right horizontally.
     * column: Items stack vertically from top to bottom (Main axis = vertical).
     * row-reverse: Items flow right to left horizontally.
     * column-reverse: Items stack from bottom to top vertically.

3. justify-content: flex-start | center | flex-end | space-between | space-around | space-evenly;
   - Controls alignment and free-space distribution along the MAIN AXIS:
     * flex-start (default): Items packed against the start of the main axis.
     * center: Items clustered together in the center.
     * flex-end: Items packed against the end of the main axis.
     * space-between: First item flush at start, last item flush at end, equal space between items.
     * space-around: Equal space around each item (half-space on outer ends).
     * space-evenly: Strictly identical spacing between items and around ends.

4. align-items: stretch | flex-start | center | flex-end | baseline;
   - Controls alignment of items along the CROSS AXIS (within a single line):
     * stretch (default): Items expand to fill the full height/cross-axis of the container.
     * flex-start: Items align at the top/start of the cross axis.
     * center: Items center vertically along the cross axis.
     * flex-end: Items align at the bottom/end of the cross axis.
     * baseline: Items align along their text baselines.

5. flex-wrap: nowrap | wrap | wrap-reverse;
   - Controls whether flex items are forced onto a single line or can wrap onto multiple lines:
     * nowrap (default): All items forced into 1 line (can shrink or overflow container).
     * wrap: Items break onto multiple lines from top to bottom when space runs out.
     * wrap-reverse: Items break onto multiple lines from bottom to top.

6. align-content: stretch | flex-start | center | flex-end | space-between | space-around | space-evenly;
   - Aligns MULTI-ROW flex lines along the CROSS AXIS when there is extra vertical space.
   - CRITICAL REQUIREMENT: Has NO EFFECT unless 'flex-wrap: wrap' is enabled and items wrap onto multiple lines!
     * space-around: Distributes wrapped rows with equal space around each row.
     * space-between: First row at top edge, last row at bottom edge, equal space between rows.
     * center: All rows packed tightly in the vertical center of the container.
     * stretch: Rows stretch to take up equal portions of the vertical height.

7. gap (row-gap, column-gap):
   - Sets precise spacing/gutters directly between flex items without needing margin hacks.
   - Example: gap: 15px; (15px gap between both rows and columns).

--------------------------------------------------------------------------------
5.2. FLEX ITEM PROPERTIES (APPLIED TO INDIVIDUAL CHILDREN)
--------------------------------------------------------------------------------

1. order: <integer>;
   - Controls the visual rendering order of flex items without changing the HTML source code!
   - Default value: 0.
   - Lower numbers appear earlier (e.g., -1 appears before 0).
   - Higher numbers appear later (e.g., order: 5 moves an item to the end).
   - Example (from 06_flexbox/flexbox.html):
     Item 1 has order: 5; Item 2 has order: 4; Item 5 has order: 1 -> Reverses visual order!

2. flex-grow: <number>;
   - Specifies what fraction of the remaining extra space in the container an item should absorb along the main axis.
   - Default value: 0 (items do not grow beyond their base content size).
   - Proportional Growth:
     * If all items have flex-grow: 1, available space is shared equally.
     * If item 1 has flex-grow: 1, and item 2 has flex-grow: 5:
       Item 2 grows 5 times faster and absorbs 5x more free space than item 1!

3. flex-shrink: <number>;
   - Determines how much an item will shrink relative to siblings when the container runs out of space.
   - Default value: 1 (items shrink proportionally to avoid overflow).
   - flex-shrink: 0 prevents an item from ever shrinking below its base width.

4. flex-basis: <length> | auto;
   - Defines the initial default size of an item before any flex-grow or flex-shrink space distribution occurs.
   - Default value: auto (sizes according to content or declared width/height).

5. flex shorthand:
   - flex: <flex-grow> <flex-shrink> <flex-basis>;
   - Common presets:
     * flex: 1; -> shorthand for flex: 1 1 0%; (flexible, equal size items).
     * flex: 0 0 200px; -> fixed non-growing, non-shrinking 200px card.

6. align-self: auto | flex-start | center | flex-end | baseline | stretch;
   - Allows an INDIVIDUAL flex item to override the container's align-items property!
   - Values:
     * flex-start: Item snaps to the start of the cross axis.
     * center: Item centers along the cross axis.
     * flex-end: Item snaps to the bottom/end of the cross axis.
     * stretch: Item stretches to occupy full container cross-axis height (must not have fixed height, e.g. height: auto).
     * auto (default): Inherits the parent container's align-items value.

--------------------------------------------------------------------------------
5.3. COMMON FLEXBOX RECIPES & PATTERNS
--------------------------------------------------------------------------------

A. THE PERFECT CIRCLE RECIPE (FLEX INSIDE A CIRCLE):
To build a perfectly circular badge/avatar with centered text inside:
.circle {
    width: 50px;
    height: 50px;
    border-radius: 50%;          /* Turns square box into a circle */
    display: flex;               /* Activates flexbox inside circle */
    justify-content: center;     /* Centers text horizontally */
    align-items: center;         /* Centers text vertically */
    font-weight: bold;
    margin: 5px;
}

B. THE FULL-PAGE VIEWPORT CENTERING RECIPE:
To center a modal, login box, or hero card in the exact middle of the browser screen:
body {
    margin: 0;
    height: 100vh;             /* Occupies 100% of visible viewport height */
    display: flex;             /* Activates Flexbox container */
    justify-content: center;   /* Centers horizontally along main axis */
    align-items: center;       /* Centers vertically along cross axis */
    background-color: #1a1a1a;
}

C. VERTICAL FORM FIELD STACKING:
form {
    display: flex;
    flex-direction: column;    /* Stacks child inputs top-to-bottom */
    gap: 12px;                 /* Modern clean spacing between inputs */
}

6. CSS GRID LAYOUT (2D ARCHITECTURE & GRID MASTERCLASS)
================================================================================

CSS Grid Layout is the most powerful 2-dimensional layout system in CSS. While
Flexbox handles 1-dimensional layouts (either a row OR a column at a time),
CSS Grid controls BOTH rows and columns simultaneously in a unified matrix.

--------------------------------------------------------------------------------
FLEXBOX vs CSS GRID: WHEN TO USE WHAT?
--------------------------------------------------------------------------------
- Use FLEXBOX when:
  * You need 1D alignment (single row or single column).
  * Content dictates the sizing (e.g. navigation bars, button groups, centering a card).
  * Items wrap naturally without aligning to a rigid grid column structure.
- Use CSS GRID when:
  * You need 2D control (rows AND columns at the same time).
  * Layout structure dictates item placement (e.g. dashboards, photo galleries, page scaffolding).
  * You need precise spanning across multiple rows and columns (e.g. 2x2 hero card).
  * You want full-page responsive layouts with auto-fit/minmax without media queries.

--------------------------------------------------------------------------------
CORE GRID TERMINOLOGY:
--------------------------------------------------------------------------------
1. Grid Container: The parent element with 'display: grid' or 'display: inline-grid'.
2. Grid Item: The immediate direct children of the grid container.
3. Grid Lines: The invisible numbered dividing lines separating columns and rows.
   - For 3 columns, there are 4 column lines: Line 1 (start), Line 2, Line 3, Line 4 (end).
   - Negative line indices exist: -1 refers to the very last grid line.
4. Grid Track: The space between two adjacent grid lines (a row track or a column track).
5. Grid Cell: The single intersection unit of a row and a column track (like a spreadsheet cell).
6. Grid Area: Any rectangular area bounded by 4 grid lines (can span 1 or many cells).
7. Grid Gap (Gutter): The empty spacing directly between grid tracks ('gap: 10px;').

--------------------------------------------------------------------------------
6.1. GRID CONTAINER PROPERTIES (APPLIED TO PARENT)
--------------------------------------------------------------------------------

1. display: grid; (or display: inline-grid;)
   - Establishes a 2D grid formatting context on the parent container.
   - Immediate children become grid items.

2. grid-template-columns:
   - Defines the number and widths of the column tracks.
   - Track Sizing Units & Functions:
     * repeat(count, size): Shorthand to create identical columns.
       e.g., grid-template-columns: repeat(3, 1fr); -> 3 equal columns.
     * fr (Fractional Unit): Represents a fraction of the remaining free container space.
       e.g., grid-template-columns: 1fr 2fr 1fr; -> Middle column gets double the width!
     * Explicit Lengths (px, rem, %):
       e.g., grid-template-columns: 100px 200px 100px;
     * repeat(auto-fit, minmax(min, max)):
       The responsive Holy Grail! Automatically fits as many columns as possible.
       e.g., grid-template-columns: repeat(auto-fit, minmax(100px, 1fr));
       Items shrink to 100px on small screens and expand up to 1fr on large screens
       without writing a single media query!

3. grid-template-rows:
   - Defines the number and heights of the row tracks.
   - e.g., grid-template-rows: repeat(3, 100px); -> 3 rows of 100px each.
   - e.g., grid-template-rows: 100px 200px 100px; -> Row 1 is 100px, Row 2 is 200px, Row 3 is 100px.

4. gap (row-gap, column-gap):
   - Sets spacing gutters between grid cells without using margin hacks.
   - e.g., gap: 10px; (10px gap between all rows and columns).
   - e.g., gap: 20px 10px; (20px row-gap, 10px column-gap).

5. grid-template-areas:
   - Allows naming rectangular sections of the grid visually using an ASCII map.
   - Syntax:
     grid-template-areas:
       "header header header"
       "sidebar main main"
       "footer footer footer";
   - Child elements connect to these areas via 'grid-area: header;', etc.

6. align-items & justify-items:
   - align-items: stretch | start | center | end; (Vertical alignment of items within their grid cells).
   - justify-items: stretch | start | center | end; (Horizontal alignment of items within their grid cells).

--------------------------------------------------------------------------------
6.2. GRID ITEM PROPERTIES (APPLIED TO CHILDREN)
--------------------------------------------------------------------------------

1. grid-column (Line-Based Placement):
   - Specifies where an item starts and ends horizontally along column grid lines.
   - Syntax: grid-column: <start-line> / <end-line>;
   - Examples:
     * grid-column: 1 / 3; -> Starts at line 1 and ends at line 3 (spans 2 columns).
     * grid-column: 2 / 4; -> Starts at line 2 and ends at line 4 (spans 2 columns).
     * grid-column: 1 / -1; -> Spans full width from first line to very last line!
     * grid-column: span 2; -> Spans across 2 column tracks from its natural position.

2. grid-row (Line-Based Placement):
   - Specifies where an item starts and ends vertically along row grid lines.
   - Syntax: grid-row: <start-line> / <end-line>;
   - Examples:
     * grid-row: 1 / 2; -> Sits in the first row.
     * grid-row: 1 / 3; -> Spans rows 1 and 2 (making the item 2 rows tall!).

3. grid-area:
   - Named Area Assignment:
     Connects the child item to a named area defined in the parent's grid-template-areas.
     e.g., grid-area: header;
   - Coordinate Shorthand:
     grid-area: <row-start> / <col-start> / <row-end> / <col-end>;

4. Nested Grids:
   - Any grid item can also declare 'display: grid' to create a nested sub-grid!
   - Example (from gridMasterClass.html):
     Box 2 contains another grid container with 'grid-template-columns: 1fr 1fr;'
     creating a 2x2 green grid inside an outer blue grid cell!

5. Dynamic Content & Auto-Rows:
   - When items have differing content amounts (e.g. padding: 40px with long text),
     CSS Grid automatically stretches the entire row track to fit the tallest item cleanly.

--------------------------------------------------------------------------------

7. RESPONSIVE WEB DESIGN & MEDIA QUERIES (RESPONSIVE MASTERCLASS)
================================================================================

Responsive Web Design (RWD) is the practice of crafting websites that adapt
flawlessly to any screen size, device width, resolution, and orientation
(from small 320px mobile screens to 4K ultrawide displays).

--------------------------------------------------------------------------------
CORE PILLARS OF RESPONSIVE WEB DESIGN:
--------------------------------------------------------------------------------
1. THE VIEWPORT META TAG (MANDATORY IN HTML <head>):
   <meta name="viewport" content="width=device-width, initial-scale=1.0" />
   * Without this tag, mobile browsers render desktop-sized pages at 980px width
     and zoom out, resulting in unreadable microscopic text!
   * 'width=device-width' sets the viewport width to the device's physical screen.
   * 'initial-scale=1.0' sets the baseline 1:1 zoom level on initial load.

2. FLUID LAYOUTS (PERCENTAGE & FLEXIBLE WIDTHS):
   * Instead of locking containers to fixed widths (e.g. width: 900px; which breaks on mobile),
     use percentage widths (width: 100%;) or fluid constraints (max-width: 1200px;).
   * Child elements adapt dynamically as the viewport shrinks or expands.

3. RESPONSIVE MEDIA & IMAGES:
   * The Golden Rule of responsive images:
     img, video {
         max-width: 100%;
         height: auto;
     }
   * 'max-width: 100%' prevents the image from ever overflowing its parent container.
   * 'height: auto' preserves the image's original aspect ratio without distortion.

4. MEDIA QUERIES (@media):
   * CSS conditional blocks that apply styles only when certain device/viewport
     criteria (e.g. max-width, min-width, orientation) are met.
   * Syntax:
     @media (max-width: 768px) {
         /* Styles applied ONLY on screens 768px wide or smaller */
     }
     @media (min-width: 769px) {
         /* Styles applied ONLY on screens 769px wide or larger */
     }

--------------------------------------------------------------------------------
7.1. RESPONSIVE LAYOUT ENGINES (FLEXBOX vs GRID IN RWD)
--------------------------------------------------------------------------------

A. RESPONSIVE FLEXBOX (FLEX-WRAP & FLEX SHORTHAND):
   * Combining 'flex-wrap: wrap' with flex basis allows items to wrap naturally:
     .responsive-flex {
         display: flex;
         flex-wrap: wrap;
     }
     .box {
         flex: 1 1 300px; /* Grow: 1, Shrink: 1, Basis: 300px */
     }
   * On desktop (>900px): All 3 boxes sit side-by-side (each taking ~300px+).
   * On mobile (<600px): Media query switches to full width:
     @media (max-width: 600px) {
         .box {
             flex: 1 1 100%;
         }
     }

B. RESPONSIVE GRID WITHOUT MEDIA QUERIES (AUTO-FIT & MINMAX):
   * The holy grail one-liner for responsive galleries/card grids:
     .responsive-grid {
         display: grid;
         grid-template-columns: repeat(auto-fit, minmax(100px, 1fr));
         gap: 10px;
     }
   * 'minmax(100px, 1fr)': Items never shrink below 100px, but expand to fill remaining space.
   * 'auto-fit': Automatically calculates the maximum number of columns that can fit
     on the screen and reflows seamlessly across phones, tablets, and desktops!

C. MULTI-BREAKPOINT GRID (DESKTOP -> TABLET -> MOBILE):
   * Explicit tiered column degradation using media queries:
     .multi-grid {
         display: grid;
         grid-template-columns: repeat(3, 1fr); /* Desktop: 3 columns */
         gap: 10px;
     }
     @media (max-width: 800px) {
         .multi-grid {
             grid-template-columns: repeat(2, 1fr); /* Tablet: 2 columns */
         }
     }
     @media (max-width: 500px) {
         .multi-grid {
             grid-template-columns: 1fr;            /* Mobile: 1 single column */
         }
     }

--------------------------------------------------------------------------------
7.2. RESPONSIVE TYPOGRAPHY & FLUID SIZING
--------------------------------------------------------------------------------

1. VIEWPORT UNITS (vw):
   * '1vw' equals 1% of the viewport's total width.
   * font-size: 2vw; -> Font scales directly with the width of the screen.
   * Caution: On tiny mobile screens (320px), 2vw = 6.4px (illegibly small!).

2. ACCESSIBLE FLUID CALCULATION (calc()):
   * Solves the tiny mobile text problem by establishing a guaranteed base minimum:
     font-size: calc(16px + 1vw);
   * On mobile (400px width): 16px + 4px = 20px.
   * On desktop (1200px width): 16px + 12px = 28px.
   * Text remains legible on small phones while scaling gracefully on desktops!

3. MODERN CLAMP (clamp(min, preferred, max)):
   * font-size: clamp(1rem, 0.5rem + 1.5vw, 2.5rem);
   * Sets strict lower floor (1rem), upper ceiling (2.5rem), and fluid preferred rate.

--------------------------------------------------------------------------------
7.3. RESPONSIVE NAVIGATION PATTERNS (DESKTOP BAR -> MOBILE STACK)
--------------------------------------------------------------------------------

On wide screens, navigation links sit comfortably in a horizontal flex row.
On mobile viewports (<600px), media queries convert the horizontal navbar into
a touch-friendly vertical stack:

nav ul {
    list-style: none;
    display: flex;
    justify-content: space-around;
    margin: 0;
    padding: 0;
}

@media (max-width: 600px) {
    nav ul {
        flex-direction: column;    /* Switches from horizontal row to vertical column */
        align-items: center;       /* Centers links horizontally */
    }
    nav ul li {
        margin-bottom: 10px;       /* Touch-friendly separation */
    }
}

--------------------------------------------------------------------------------
7.4. RESPONSIVE UTILITIES (VISIBILITY TOGGLING)
--------------------------------------------------------------------------------

Often, desktop UI contains complex sidebars, badges, or tables that should be hidden
on mobile, while mobile viewports need simplified banners or hamburger buttons.

/* Default (Desktop) */
.hidden-on-mobile {
    display: block;
}
.visible-on-mobile {
    display: none;
}

/* Mobile Breakpoint */
@media (max-width: 600px) {
    .hidden-on-mobile {
        display: none !important;  /* Hides desktop-only elements */
    }
    .visible-on-mobile {
        display: block !important; /* Reveals mobile-only elements */
    }
}

8. COLORS, GRADIENTS & TYPOGRAPHY
================================================================================

- color:
  * Defines font color (e.g., color: #333;, color: #666;, color: #fff;).
- background / background-color:
  * Solid colors: hex (#8a2be2), named colors, rgb.
  * rgba(r, g, b, alpha): Enables opacity/transparency (e.g., rgba(255, 255, 255, 0.9)
    creates a semi-transparent frosted card backdrop).
  * linear-gradient(angle, color1, color2):
    Smooth multi-color transitions.
    Example: background: linear-gradient(135deg, #8a2be2, #4169e1);
- Google Fonts & @import:
  * External web fonts can be imported directly at the top of a CSS stylesheet:
    @import url("https://fonts.googleapis.com/css2?family=Noto+Sans:ital,wght@0,100..900;1,100..900&display=swap");
  * Applied via font-family: "Noto Sans", sans-serif;
- font-family:
  * Fallback font stack (e.g. font-family: "Noto Sans", Arial, sans-serif;).
- font-size:
  * Controls font size with units (e.g. font-size: 25px;, font-size: 1.5rem;).
- text-align:
  * Horizontal text alignment inside its container (e.g. text-align: center;).

9. CSS UNITS & FLUID SIZING (px vs rem vs vh / % / calc)
================================================================================

- px (Pixels):
  * Absolute unit representing fixed screen dots.
  * Great for borders (1px), border-radius (5px, 10px), and box shadows.

- rem (Root EM):
  * Relative unit proportional to the root <html> font-size (default is 16px).
  * Calculation: 1rem = 16px, 2rem = 32px, 0.5rem = 8px.
  * Standard for scalable, accessible typography, paddings, and margins.
  * Allows entire UI spacing to scale gracefully when user adjusts browser font size.

- vh / vw / % (Viewport Height, Width & Percentages):
  * vh: 1% of visible browser window height (100vh = full screen).
  * vw: 1% of visible browser window width (50vw = half screen).
  * %: Relative to the parent element's dimensions.
  * Full-height chain: setting height: 100% on html and body enables child
    containers (.container { height: 100%; }) to fill the full viewport accurately.

- calc() & clamp():
  * calc(base + fluid): e.g. calc(16px + 1vw) guarantees minimum size plus fluid growth.
  * clamp(min, preferred, max): Restricts sizing strictly between lower and upper bounds.

10. NAVIGATION BAR PATTERNS & UI HOVER EFFECTS
================================================================================

Navigation bars are core website components built by combining semantic HTML (<nav>, <ul>, <li>, <a>)
with CSS layout and interactive pseudo-element techniques:

1. COMMON BASE NAV RESET:
   ul {
       list-style-type: none;  /* Removes default bullet points */
       margin: 0;
       padding: 0;
   }
   a {
       text-decoration: none;   /* Removes default underline */
   }

2. VARIATION 1: HORIZONTAL FLEX NAVBAR WITH ANIMATED UNDERLINE:
   - Uses Flexbox to align links horizontally:
     ul {
         display: flex;
         justify-content: space-around;
         align-items: center;
     }
   - Sliding Underline effect via ::after pseudo-element:
     a {
         position: relative;
         padding: 5px 15px;
     }
     a::after {
         content: "";
         position: absolute;
         height: 2px;
         width: 100%;
         bottom: 0;
         left: 0;
         background-color: #0a65c7;
         transform: scaleX(0);            /* Hidden initially */
         transition: transform 0.3s ease-in-out;
     }
     a:hover::after {
         transform: scaleX(1);            /* Expands to 100% on hover */
     }

3. VARIATION 2: VERTICAL SIDEBAR NAVIGATION:
   - Uses a fixed sidebar width and block-level links:
     nav {
         width: 200px;
         padding: 20px;
         background-color: #03643c;
     }
     a {
         display: block;                  /* Fills full width of parent */
         padding: 10px;
         width: 100%;
     }
     a:hover {
         background-color: #137e0a;
     }

4. VARIATION 3: HORIZONTAL NAVBAR WITH DROPDOWN MENU:
   - Nested dropdown container hidden by default:
     .dropdown-content {
         display: none;
     }
   - Revealed on parent hover using absolute positioning:
     .dropdown:hover .dropdown-content {
         display: block;
         position: absolute;
         background-color: #3e3e3e;
         min-width: 150px;
     }

11. VISUAL POLISH & COMPONENT PATTERNS (SHADOWS, TRANSITIONS, IMAGES)
================================================================================

1. BOX SHADOW (box-shadow):
   - Adds realistic elevation, depth, and drop-shadows to cards and buttons.
   - Syntax: box-shadow: offset-x offset-y blur-radius color;
   - Example: box-shadow: 0 4px 6px rgba(0, 0, 0, 0.2);

2. SMOOTH TRANSITIONS (transition):
   - Smoothly animates property changes on pseudo-classes (:hover) rather than snapping abruptly.
   - Syntax: transition: property duration timing-function;
   - Example:
     button {
         background-color: #8a2be2;
         transition: background-color 0.3s ease-in-out;
     }
     button:hover {
         background-color: #7a1dd1;
     }

3. IMAGE FIT & RESPONSIVENESS (object-fit):
   - Controls how an <img> or video resizes to fit its container box:
     * object-fit: contain; (scales image to fit within dimensions while preserving aspect ratio)
     * object-fit: cover; (crops image to fill dimensions completely)

4. RESPONSIVE CONTAINER CONSTRAINTS (max-width):
   - max-width: 400px; keeps a card compact on desktop screens, while allowing it
     to scale down fluidly on smaller mobile viewports.

5. THE COMING SOON / HERO LANDING PAGE RECIPE:
   - Full-bleed gradient background:
     html, body { height: 100%; margin: 0; }
     .container { height: 100%; background: linear-gradient(135deg, #8a2be2, #4169e1); display: flex; justify-content: center; align-items: center; }
   - Centered card:
     .content { background-color: rgba(255, 255, 255, 0.9); padding: 2rem; border-radius: 10px; max-width: 400px; text-align: center; }
